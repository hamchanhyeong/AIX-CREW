# 재기지원 사업 규정 작성 지원 (AIX-CREW 과제 04)

중소벤처기업진흥공단 창업지원처 담당자가 운영계획(안)과 참고 규정으로 **재기지원 사업 운영규칙 초안 1부**, **운영요령 초안 1부**, **계획 변경에 따른 신구대비표**를 작성·검토하는 업무 도구입니다(Next.js 웹 애플리케이션).

```
자료 입력 → 주요 조건 확인 → 근거 연결 → 조문 초안 작성 → 사람 검수 → 변경 계획 반영 → 문서 다운로드
```

> 모든 결과는 **검토용 초안**입니다. 기관 승인이나 법적 적합성을 보장하지 않습니다.
> 샘플 작업공간의 계획안·참고 규정·수치(예: 지원 한도 1억원→1.5억원)는 **시연용 가상 자료**이며 실제 사업 조건이 아닙니다.

## 실행 (Windows)

Node.js LTS가 필요합니다(https://nodejs.org).

**가장 쉬운 방법**: 폴더의 **`실행.bat`을 더블클릭**합니다.
- 처음 한 번은 필요한 파일을 자동으로 설치합니다(몇 분, 인터넷 필요).
- 서버가 켜지면 브라우저가 http://localhost:3000 으로 열립니다. 처음에는 화면이 뜨는 데 몇 초 걸릴 수 있습니다.
- 검은 창을 닫으면 프로그램이 종료됩니다.

**터미널에서 실행** (PowerShell은 `npm` 대신 `npm.cmd`, 명령은 한 줄씩):

```powershell
npm.cmd install
```

```powershell
npm.cmd run dev
```

운영 모드(더 빠름):

```powershell
npm.cmd run build
```

```powershell
npm.cmd start
```

> 프로젝트 폴더를 OneDrive 밖(예: `C:\dev\aix-crew`)에 두면 설치 오류가 줄어듭니다.

## 환경변수 (실제 AI 모드, 선택)

`.env.example`을 `.env.local`로 복사하고 값을 채운 뒤 서버를 다시 시작합니다. 키가 없어도 다른 기능은 모두 동작합니다.

| 변수 | 설명 | 기본값 |
| --- | --- | --- |
| `LLM_PROVIDER` | LLM 제공자(현재 `anthropic`) | `anthropic` |
| `LLM_MODEL` | 모델 ID | `claude-opus-5-5` |
| `ANTHROPIC_API_KEY` | API 키. 서버에서만 읽음 | 없음(없으면 AI 기능 비활성) |
| `LLM_REFUSAL_FALLBACK` | 거절 시 서버 측 대체 모델 사용(`off`로 끔) | `on` |
| `DATA_DIR` | 작업 데이터 저장 폴더 | `./data` |

## 데모 모드와 실제 AI 모드

| | 데모 모드(샘플 작업공간) | 실제 AI 모드(실제 작업공간 + 키 설정) |
| --- | --- | --- |
| 자료 | 가상 계획안·가상 유사사업 규정, 법령·지침은 ‘원문 미등록’ 목록 | 담당자가 등록한 자료 |
| 초안 | 조문 템플릿 + 확인된 조건 값(AI 분석 아님) | 템플릿으로 뼈대 작성 후 조항별 **AI 작성 제안** |
| AI 호출 | 하지 않음 | 서버에서 호출. 관련 원문 조각만 전송, 외부 전송 금지 자료·배경자료 제외 |
| 검증 | — | 응답 형식, 출처 ID, 인용 문구 원문 대조, 원문에 없는 법령 조문 번호 차단 |
| 실패 | — | 시간 초과·API 오류·빈 응답·검증 실패를 그대로 표시(데모 결과로 대체하지 않음) |

## 시연 순서

1. **프로젝트 현황**에서 `샘플 프로젝트 시작`
2. **자료 관리**에서 가상 운영계획(안)·가상 유사사업 규정 원문 확인
3. **사업 조건 확인**에서 값이 있는 조건을 `확정`(빈 값은 미확정 유지) → `조건 확인 완료`
4. **규정 편집기**에서 `운영규칙·요령 초안 작성`
5. 운영규칙 `제6조(지원 한도)` 선택 → 오른쪽 근거 패널에서 운영계획 원문·인용 확인
6. 본문 수정 → `저장` → `검토 완료`
7. **계획 변경·신구대비표**에서 `가상 계획 v2 등록`(지원 한도 1억원→1.5억원)
8. `② 연결 조항 찾기 · ③ 수정안 생성` → 지원 한도와 연결된 3개 조항만 제안(같은 ‘1억원’이 있는 자산 취득 기준 조항은 그대로)
9. 2건 `⑤ 반영`, 1건 `보류` → `⑥ 반영 결과를 새 버전으로 저장`
10. `신구대비표.docx 다운로드`, **내보내기·백업**에서 운영규칙·요령 초안 다운로드
11. 새로고침 → 반영 본문, ‘재검토 필요’ 상태, 보류 항목(검토 목록의 ‘조건 값 불일치’)이 그대로 복원

## 주요 기능

- **프로젝트 현황**: 작업 단계, 등록 자료 수, 문서별 작성·검토 진행률, 근거 미확인 조항 수, 미확정 조건 수
- **자료 관리**: 운영계획(안)/법령·시행령/지침/유사사업 규정/배경자료 구분과 메타데이터. TXT·텍스트 PDF(페이지 보존)·DOCX 업로드 또는 붙여넣기. HWP·스캔 PDF는 안내 후 거절. 원문 조각 확인·수정
- **사업 조건**: ‘항목: 값’ 형식에서 규칙 기반 추출, 값·원문 위치·확정 상태·담당자 확인. 빈 값은 채우지 않음
- **규정 편집기**: 목차(운영규칙 8개 장 / 운영요령 4개 편) · 조항 편집 · 근거 패널(적용 근거 후보 / 유사사업 참고 / 운영계획 반영 / 근거 확인 필요). 조항 추가·삭제·순서 변경, 메모, 검토 상태, 조항별 재작성 제안(템플릿·AI)
- **검토 목록**: 근거 원문 미등록·미연결, 인용 불일치, 미확정 조건, 조건 값 불일치, 중복·누락 조항, 없는 내부 참조, 미검토 조항 — 프로그램 점검과 AI 검토사항 분리
- **계획 변경·신구대비표**: 조건 비교 → 조건 ID·조항 ID 연결로 영향 조항 탐색 → 수정안 → 개별 반영·보류 → 새 버전 저장. 비교 기준 3가지
- **내보내기**: 운영규칙 초안.docx, 운영요령 초안.docx, 신구대비표.docx, 근거 매핑표.csv, 작업 백업.json, 백업 복원

## 데이터 저장 위치와 한계

- 단일 사용자 로컬 MVP입니다. 작업 내용은 서버를 실행한 폴더의 `data/workspace-main.json`(실제)과 `data/workspace-sample.json`(샘플)에 저장됩니다. `data/`는 Git에 올라가지 않습니다.
- 다른 PC로 옮기거나 보관할 때는 **내보내기·백업 → 작업 백업.json**을 받아 다른 PC에서 ‘백업 복원’으로 엽니다.
- 초기화: **설정 → 실제 작업공간 초기화**, 또는 서버를 멈추고 `data/`의 해당 파일 삭제
- 인증·동시 편집이 없습니다. **기관 자료가 들어 있는 상태로 외부에 배포하지 마세요.**
