# 재기지원 사업 규정 작성 지원 도구 (AIX-CREW 과제 04)

중소벤처기업진흥공단 창업지원처 담당자가 운영계획(안)과 참고 규정으로 **재기지원 사업 운영규칙 초안 1부**, **운영요령 초안 1부**, **계획 변경에 따른 신구대비표**를 작성·검토하는 업무 도구입니다.

```
자료 입력 → 주요 조건 확인 → 근거 연결 → 조문 초안 작성 → 사람 검수 → 변경 계획 반영 → 문서 다운로드
```

> 모든 결과는 **검토용 초안**입니다. 기관 승인이나 법적 적합성을 보장하지 않습니다.
> 샘플 작업공간의 계획안·참고 규정·수치(예: 지원 한도 1억원→1.5억원)는 **시연용 가상 자료**이며 실제 사업 조건이 아닙니다.

## 설치·실행

Node.js 20 이상이 필요합니다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. 운영 모드로 실행하려면 다음을 사용합니다.

```bash
npm run build
```

```bash
npm start
```

## 환경변수 (실제 AI 모드)

`.env.example`을 `.env.local`로 복사하고 값을 채운 뒤 서버를 다시 시작합니다.

| 변수 | 설명 | 기본값 |
| --- | --- | --- |
| `LLM_PROVIDER` | LLM 제공자. 현재 `anthropic` 구현 | `anthropic` |
| `LLM_MODEL` | 모델 ID | `claude-opus-5-5` |
| `ANTHROPIC_API_KEY` | API 키. 서버에서만 읽음 | 없음(없으면 AI 기능 비활성) |
| `LLM_REFUSAL_FALLBACK` | 거절 시 서버 측 대체 모델 사용(`off`로 끔) | `on` |
| `DATA_DIR` | 작업 데이터 저장 폴더 | `./data` |

키는 브라우저 코드·응답·로그에 노출되지 않습니다(`/api/ai/status`는 설정 여부와 모델명만 반환).

## 데모 모드와 실제 AI 모드

| | 데모 모드 (샘플 작업공간) | 실제 AI 모드 (실제 작업공간 + 키 설정) |
| --- | --- | --- |
| 자료 | 가상 계획안·가상 유사사업 규정·가상 보도 메모, 법령·지침은 ‘원문 미등록’ 목록 | 담당자가 등록한 자료 |
| 초안 작성 | 조문 템플릿 + 확인된 조건 값 (AI 분석 아님) | 같은 템플릿으로 뼈대 작성 후, 조항별 **AI 작성 제안** |
| AI 호출 | 하지 않음 | 서버에서 호출. 관련 원문 조각만 전송, 외부 전송 금지 자료·배경자료 제외 |
| 검증 | — | 응답 스키마 검증, 출처 ID 존재 확인, 인용 문구 원문 대조, 원문에 없는 법령 조문 번호 차단 |
| 실패 처리 | — | 시간 초과·API 오류·빈 응답·형식 오류·검증 실패를 그대로 표시(데모 결과로 대체하지 않음) |
| 편집·검토·변경 비교·저장·다운로드 | 실제 동작 | 실제 동작 |

## 샘플 사용 (시연 순서)

1. **프로젝트 현황**에서 `샘플 프로젝트 시작`
2. **자료 관리**에서 가상 운영계획(안)·가상 유사사업 규정 원문 확인
3. **사업 조건 확인**에서 추출된 조건 확인 → 값이 있는 조건을 `확정`, 빈 값은 미확정으로 두고 `조건 확인 완료`
4. **규정 편집기**에서 `운영규칙·요령 초안 작성`
5. 운영규칙 `제6조(지원 한도)` 선택 → 우측 근거 패널에서 운영계획 원문·인용 확인
6. 본문 수정 → `저장` → `검토 완료`
7. **계획 변경·신구대비표**에서 `가상 계획 v2 등록`(지원 한도 1억원→1.5억원, 시연용)
8. `② 연결 조항 찾기 · ③ 수정안 생성` → 지원 한도 조건과 연결된 3개 조항만 제안 (같은 ‘1억원’이 있는 자산 취득 기준 조항은 바뀌지 않음)
9. 2건 `⑤ 반영`, 1건 `보류` → `⑥ 반영 결과를 새 버전으로 저장`
10. `신구대비표.docx 다운로드`, **내보내기·백업**에서 운영규칙·요령 초안 다운로드
11. 새로고침 → 반영 본문·재검토 필요 상태·보류 항목(검토 목록의 ‘조건 값 불일치’)이 그대로 복원

## 주요 기능

- **프로젝트 현황**: 작업 단계, 최근 수정일, 등록 자료 수, 문서별 작성·검토 진행률, 근거 미확인 조항 수, 미확정 조건 수(모두 저장 데이터로 계산)
- **자료 관리**: 운영계획(안)/법령·시행령/지침/유사사업 규정/배경자료 구분, 버전·기준일·출처 URL·공개 여부·외부 전송 허용·원문 상태·적용 여부. TXT·텍스트 PDF·DOCX 업로드와 직접 붙여넣기. 원문 조각(페이지 `p.N ¶M` 또는 절·문단 식별자) 확인·수정
- **사업 조건**: 규칙 기반 추출(‘항목: 값’ 형식), 값·원문 위치·확정 상태·담당자 확인. 빈 값은 채우지 않음
- **규정 편집기**: 목차(운영규칙 8개 장 / 운영요령 4개 편, 편집 가능) · 조항 편집 · 근거 패널(적용 근거 후보 / 유사사업 참고 / 운영계획 반영 / 작성 제안·근거 확인 필요). 조항 추가·삭제·순서 변경, 메모, 검토 상태, 조항별 재작성 제안(템플릿·AI), 제안 적용 여부 선택
- **검토 목록**: 근거 원문 미등록, 근거 미연결, 인용 불일치, 미확정 조건, 조건 값 불일치, 중복·누락 조항, 존재하지 않는 내부 참조, 미검토 생성 조항 — 프로그램 점검과 AI 제안 검토사항을 분리
- **계획 변경·신구대비표**: 조건 비교 → 조건 ID·조항 ID 연결로 영향 조항 탐색 → 수정안 → 변경 전·후 비교 → 개별 반영·보류 → 새 버전 저장. 비교 기준: 이전 초안↔계획 반영 초안(기본), 저장 버전 간, 유사사업 참고 규정↔새 초안(참고용)
- **내보내기**: 운영규칙 초안.docx, 운영요령 초안.docx, 신구대비표.docx, 근거 매핑표.csv(UTF-8 BOM), 작업 백업.json, 백업 복원

## 데이터 저장 위치와 한계

- 단일 사용자 로컬 MVP입니다. 작업 내용은 서버의 `data/workspace-main.json`(실제 작업공간)과 `data/workspace-sample.json`(샘플)에 저장됩니다. `data/`는 `.gitignore`에 포함되어 Git에 올라가지 않습니다.
- 브라우저는 변경 후 약 0.5초 뒤 서버에 자동 저장하며, 상단에 저장 상태가 표시됩니다.
- 인증·권한·동시 편집 충돌 처리가 없습니다. **기관 자료가 들어 있는 상태로 외부에 배포하지 마세요.**
- 기관 SSO, 전자결재 연동, 실시간 공동편집은 범위 밖입니다.

### 데이터 초기화

- 화면: **설정 → 실제 작업공간 초기화**(또는 샘플을 처음 상태로)
- 파일: 서버를 멈추고 `data/workspace-main.json` 또는 `data/workspace-sample.json` 삭제

### 백업·복원

- **내보내기·백업 → 작업 백업.json 다운로드**: 작업공간 전체(원문 포함). 비공개 자료가 들어 있을 수 있으니 보관에 주의하세요.
- **백업 복원**: 같은 화면에서 JSON 파일 선택 → 형식 확인 후 현재 작업공간을 덮어씀

## 구조

```
app/            화면(현황·자료·조건·편집기·검토·변경·내보내기·설정)과 API 라우트
components/     공통 UI, 작업공간 상태(자동 저장), 편집기 패널
lib/            도메인 로직(순수 함수): 템플릿·초안·점검·변경 비교·내보내기·AI 검증
lib/server/     파일 저장소, 업로드 파싱
tests/          Vitest 단위·통합 테스트
scripts/        브라우저 시연 흐름 자동 실행
```

조문 번호는 순서로 계산하고 조항 ID와 분리되어 있어, 순서를 바꿔도 조건·근거 연결이 유지됩니다.
