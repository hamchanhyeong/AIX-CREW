# 재기지원 사업 규정 작성 지원 (AIX-CREW 과제 04)

중소벤처기업진흥공단 창업지원처 담당자가 운영계획(안)과 참고 규정으로 **재기지원 사업 운영규칙 초안 1부**, **운영요령 초안 1부**, **계획 변경에 따른 신구대비표**를 작성·검토하는 도구입니다. 제출물은 **정적 반응형 웹(`site/`)**입니다.

```
자료 입력 → 주요 조건 확인 → 근거 연결 → 조문 초안 작성 → 사람 검수 → 변경 계획 반영 → 문서 다운로드
```

> 모든 결과는 **검토용 초안**입니다. 기관 승인이나 법적 적합성을 보장하지 않습니다.
> 샘플의 계획안·참고 규정·수치(예: 지원 한도 1억원→1.5억원)는 **시연용 가상 자료**이며 실제 사업 조건이 아닙니다.

## 실행

정적 반응형 웹입니다. PC·태블릿·휴대폰 화면에 맞춰 배치가 바뀌고, 서버나 설치 없이 동작합니다.

- **내 PC에서 열기**: `site/index.html`을 더블클릭해 Chrome이나 Edge로 엽니다. `site/` 폴더 전체(`index.html`, `assets/`)가 함께 있어야 합니다.
- **주소로 공유하기**: `site/` 폴더를 GitHub Pages 같은 정적 호스팅에 올리면 휴대폰에서도 주소로 열 수 있습니다. 인증이 없으므로 기관 자료가 든 상태로 공개하지 마세요(데이터는 각자 브라우저에만 저장됨).
- 데이터는 그 브라우저의 localStorage에만 저장됩니다. 다른 기기로 옮기거나 브라우저 데이터를 지우기 전에 **내보내기·백업 → 작업 백업.json**을 받아 두고, 같은 화면의 ‘백업 복원’으로 되살립니다.
- 데이터 초기화: **내보내기·백업 → 실제 작업공간 초기화**(샘플은 ‘샘플을 처음 상태로’).

| 화면 폭 | 배치 |
| --- | --- |
| 1280px 이상 (PC) | 왼쪽 메뉴 고정, 규정 편집기 3단(목차·조항·근거) |
| 768~1279px (태블릿·작은 노트북) | ☰ 버튼으로 여는 서랍 메뉴, 편집기는 [목차·조항 편집·근거·검토] 탭 |
| 767px 이하 (휴대폰) | 1열 배치, 표는 카드형(칸마다 열 이름), 큰 터치 버튼 |

## 시연 순서

1. **프로젝트 현황**에서 `샘플 프로젝트 시작`
2. **자료 관리**에서 가상 운영계획(안)·가상 유사사업 규정 원문 확인
3. **사업 조건 확인**에서 값이 있는 조건을 `확정`(빈 값은 미확정 유지) → `조건 확인 완료`
4. **규정 편집기**에서 `운영규칙·요령 초안 작성`
5. 운영규칙 `제6조(지원 한도)` 선택 → 오른쪽 근거 패널에서 운영계획 원문·인용 확인
6. 본문 수정 → `저장` → `검토 완료`
7. **계획 변경·신구대비표**에서 `가상 계획 v2 등록`(지원 한도 1억원→1.5억원)
8. `② 연결 조항 찾기 · ③ 수정안 생성` → 지원 한도와 연결된 3개 조항만 제안(같은 ‘1억원’이 있는 자산 취득 기준 조항은 그대로)
9. 2건 `⑤ 반영`, 1건 `보류` → `⑥ 반영 결과를 새 버전으로 저장`
10. `신구대비표.docx 다운로드`, **내보내기·백업**에서 운영규칙·요령 초안 다운로드
11. 새로고침 → 반영 본문, ‘재검토 필요’ 상태, 보류 항목(검토 목록의 ‘조건 값 불일치’)이 그대로 복원

## 주요 기능

- **프로젝트 현황**: 작업 단계, 등록 자료 수, 문서별 작성·검토 진행률, 근거 미확인 조항 수, 미확정 조건 수(저장 데이터로 계산)
- **자료 관리**: 운영계획(안)/법령·시행령/지침/유사사업 규정/배경자료 구분, 버전·기준일·출처·공개 여부·원문 상태·적용 여부. TXT 파일·붙여넣기로 원문 등록, 원문 조각 확인·수정
- **사업 조건**: ‘항목: 값’ 형식의 줄에서 규칙 기반 추출. 값·원문 위치·확정 상태·담당자 확인. 빈 값은 채우지 않음
- **규정 편집기**: 목차(운영규칙 8개 장 / 운영요령 4개 편) · 조항 편집 · 근거 패널(적용 근거 후보 / 유사사업 참고 / 운영계획 반영 / 근거 확인 필요). 조항 추가·삭제·순서 변경, 메모, 검토 상태, 템플릿 재작성 제안
- **검토 목록**: 근거 원문 미등록·미연결, 인용 불일치, 미확정 조건, 조건 값 불일치, 중복·누락 조항, 없는 내부 참조, 미검토 조항
- **계획 변경·신구대비표**: 조건 비교 → 조건 ID·조항 ID 연결로 영향 조항 탐색 → 수정안 → 개별 반영·보류 → 새 버전 저장. 비교 기준 3가지(이전 초안↔계획 반영, 버전 간, 유사사업 참고↔새 초안)
- **내보내기**: 운영규칙 초안.docx, 운영요령 초안.docx, 신구대비표.docx, 근거 매핑표.csv, 작업 백업.json

## 범위 밖

AI 작성 제안(API 키를 브라우저 파일에 둘 수 없음), PDF·DOCX·HWP 원문 추출, OCR, 로그인·공동편집·전자결재.

## 수정·재생성 (개발용, Node.js 필요)

화면은 `web/`, 조문 템플릿·점검·변경 처리·내보내기 로직은 `lib/`에 있습니다. 수정한 뒤 `site/`를 다시 만듭니다.

```bash
npm install
```

```bash
npm run build
```

검증:

```bash
npm run typecheck
```

```bash
npm test
```

```bash
npm run e2e
```

(`npm run e2e`는 Playwright가 설치된 환경에서 `site/index.html`을 열어 시연 1~11단계와 390~1440px 반응형 점검을 자동 실행합니다.)

```
site/           제출물(생성 결과): index.html + assets/app.js, assets/style.css
web/            화면 코드(app.ts, style.css, index.html)
lib/            도메인 로직: 템플릿·초안·점검·계획 변경·신구대비표·내보내기
tests/          Vitest 테스트
scripts/        site/ 빌드, 시연 흐름·반응형 자동 검증
docs/           과제 브리프, spec, plan
validation/     검증 기록
ai-log/         AI 작업 기록
```
