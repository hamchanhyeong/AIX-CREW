# spec.md — 무엇을 만들지 못 박는다

> 규칙 번호(R-x)는 커밋 메시지·테스트·검증 기록에서 같은 번호로 부른다.
> 기대 결과는 [정답.md](../정답.md)에 사람이 먼저 손으로 적고, 결과물과 대조한다.

## 1. 목적
담당자가 운영계획(안)과 참고 규정으로 운영규칙·운영요령 검토용 초안을 만들고, 계획 변경을 연결된 조항에만 반영해 신구대비표로 내보낸다. ([intent.md](../intent.md))

## 2. 사용자와 실행 환경
- 사용자: 창업지원처 규정 작성 담당자 1인(단일 사용자)
- 실행: `index.html`을 Chrome·Edge에서 직접 연다. 설치·서버·인터넷 불필요
- 저장: 브라우저 localStorage. 백업·복원은 JSON 파일
- PC 화면 1280px·1440px 기준

## 3. 입력
| 입력 | 형식 | 비고 |
| --- | --- | --- |
| 자료 | TXT 파일 또는 붙여넣기 | 유형: 운영계획(안)/법령·시행령/지침/유사사업 규정/배경자료 |
| 자료 정보 | 문서명·유형·버전·기준일·출처 URL·공개 여부·적용 여부 | 원문 없이 목록만 등록 가능(‘원문 미등록’) |
| 사업 조건 | 운영계획(안)의 ‘- 항목: 값’ 줄 또는 직접 입력 | 공통 5개 + 사업별 6개 × 3 = 23개 칸 |
| 담당자 판단 | 조건 확정, 조항 수정, 검토 상태, 제안 반영·보류 | |

## 4. 출력
| 출력 | 내용 |
| --- | --- |
| 운영규칙 초안.docx | 8개 장, 조문, 검토 상태, 부록 ‘조항별 근거 목록’ |
| 운영요령 초안.docx | 공통편 + 사업별 3개 편, 부록 근거 목록 |
| 신구대비표.docx | 문서·조항 / 변경 전 / 변경 제안 / 변경 사유 / 관련 계획·근거 / 반영 상태 |
| 근거 매핑표.csv | 조항 × 근거(역할·자료·버전·위치·인용·원문 상태·연결 조건), UTF-8 BOM |
| 작업 백업.json | 작업공간 전체 |

모든 파일에 프로젝트명·버전·작성일·‘검토용 초안’ 표시, 샘플이면 ‘시연용 가상 자료’ 표시.

## 5. 규칙
### 자료·조건
- **R1** 자료는 5개 유형으로 구분한다. 근거 역할은 유형으로 정한다: 법령·지침→적용 근거 후보, 유사사업 규정→유사사업 참고, 운영계획→운영계획 반영. 배경자료는 근거로 연결하지 않는다.
- **R2** 원문이 없는 자료는 ‘원문 미등록’으로 표시하고, 그 자료를 근거로 한 조항은 검토 목록에 올린다.
- **R3** 원문은 줄 단위 조각으로 나누고 위치(절·문단 또는 조문 제목)를 남긴다. 조각을 고치면 원문 버전이 올라간다.
- **R4** 조건 추출은 ‘항목: 값’ 형식만 인식한다. 추출 값은 모두 ‘미확정’으로 들어오고, ‘미정’·빈 값은 채우지 않는다.
- **R5** 값이 빈 조건은 ‘확정’할 수 없다. 담당자가 ‘조건 확인 완료’를 해야 초안을 만들 수 있다.

### 초안·편집
- **R6** 초안은 운영규칙 1부(8개 장)와 운영요령 1부(4개 편)로 만든다. 사업마다 문서를 따로 만들지 않는다.
- **R7** 조문의 사업 조건 값은 연결된 조건으로만 채운다. 빈 값은 【확인 필요: 항목】, 미확정 값은 `값【미확정】`으로 쓴다.
- **R8** 원문이 없는 법령 조문 번호·인용을 본문에 만들지 않는다. 근거 원문이 없는 조항은 ‘작성 제안·근거 확인 필요’로 표시한다.
- **R9** 조문 번호는 순서로 계산하고, 조항 ID는 순서가 바뀌어도 유지한다.
- **R10** 검토 상태는 검토 대기/수정 필요/검토 완료/재검토 필요. 검토 완료 조항을 수정하거나 연결 근거의 원문 버전이 바뀌면 ‘재검토 필요’로 바꾼다.
- **R11** 재작성 제안은 바로 적용하지 않는다. 담당자가 반영/보류/반영 안 함을 고른다.

### 검토 목록
- **R12** 프로그램이 다음을 점검해 조항과 연결해 보여준다: 근거 원문 미등록, 근거 미연결, 인용 불일치, 미확정 조건, 조건 값 불일치, 조항 제목 중복·본문 누락, 없는 내부 참조(‘제N조’), 미검토 생성 조항. 항목을 누르면 해당 조항으로 이동한다.

### 계획 변경·신구대비표
- **R13** 새 계획(안) 또는 직접 입력으로 이전·신규 조건을 비교하고, 바뀐 조건만 보여준다.
- **R14** 바뀐 조건과 **연결된 조항만** 수정안을 만든다. 같은 숫자가 있어도 연결되지 않은 조항은 바꾸지 않으며, 미연결 조항 수를 ‘자동 검토 범위 밖’으로 표시한다.
- **R15** 수정안은 현재 본문(담당자 수정본 포함)에서 해당 값만 바꾼다. 이전 값을 찾지 못하면 자동 수정하지 않고 직접 수정 필요로 표시한다.
- **R16** 제안 생성 후 조항이 수정되었으면 반영을 막는다(담당자 수정본 보호).
- **R17** 변경 전 상태는 자동으로 버전 저장하고, 반영 결과는 담당자가 새 버전으로 저장한다.
- **R18** 신구대비표 비교 기준: 기본 ‘이전 초안 ↔ 계획 반영 초안’, 선택 ‘저장 버전 간’, ‘유사사업 참고 규정 ↔ 새 초안’. 유사사업 규정을 ‘현행 규정’이라 부르지 않는다. 추가·삭제·수정은 색과 [배지]로 함께 표시한다.

### 저장·내보내기
- **R19** 모든 변경은 즉시 저장되고 새로고침 후 복원된다. 샘플과 실제 작업공간은 따로 저장한다.
- **R20** 내보낸 파일에 검토용 초안 표시, 【확인 필요】·【미확정】 표시, 근거 목록을 유지한다.

## 6. 수용 기준 (시연 시나리오)
1 샘플 시작 → 2 가상 계획·참고 규정 확인 → 3 미확정 조건 확인 → 4 초안 생성 → 5 조항 원문 확인 → 6 수정·검토 완료 → 7 지원 한도 1억원→1.5억원 → 8 연관 조항만 제안 → 9 일부 반영·일부 보류 → 10 초안·신구대비표 다운로드 → 11 새로고침 후 복원.
자동 검증: `npm run e2e`, `npm test`. 결과 기록: [validation/](../validation/).
